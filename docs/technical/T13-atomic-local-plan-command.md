# T13 — Atomic local-plan command persistence

Migration 0007 introduces a SECURITY INVOKER PostgreSQL function which inserts a center plan, append-only command audit and append-only outbox event in the same database transaction. The function requires explicit IDs, actor subject, correlation ID, a valid JSON activity array and an existing published national version (via foreign key). Any error in the second or third insert rolls back the first insert as well. PUBLIC execution is revoked and no application runtime role is granted access. CI executes successful and failing commands against a disposable PostgreSQL database, asserting all-or-nothing behavior for unpublished versions, duplicate audit IDs and duplicate event IDs, and denying execution to an untrusted role.

**This is not a live authorized API.** The database function cannot authenticate the supplied actor or determine headquarters/center permissions. It must not be granted to a runtime role until verified OIDC identity, current active center membership, approved operation-specific permissions, secure tenant scope, concurrency/idempotency semantics and deployment grants are designed and tested. The function is not idempotent: retries with reused identifiers fail rather than replaying success. Event delivery is not implemented. No Production migration was applied.
