# T12 — Center row isolation at PostgreSQL boundary

Migration 0006 enables and forces row-level security on center program plans and center memberships. The only allowed row scope is an exact match to the transaction/session setting `kanoonyar.center_id`; absent or empty setting yields no visible rows and rejects inserts. The CI test uses a non-owner role without BYPASSRLS, verifies missing scope, center-A visibility and cross-center insert denial. It runs in a separate disposable PostgreSQL database.

**Security limitation:** Any SQL principal with permission to set custom PostgreSQL settings could forge `kanoonyar.center_id`. RLS here is defense-in-depth, not proof of authorization or tenant identity. Before production, verified Keycloak/OIDC subject and authoritative active membership must be checked by the server, scope set using `SET LOCAL` inside the same transaction, database credentials and grants isolated, and a robust mechanism preventing arbitrary tenant-setting manipulation approved and tested. No API mutation or runtime access is enabled by this migration. Headquarters cross-center reporting requires its own explicit authorized read path; do not disable RLS for convenience.
